## [1.6.1] - 2026-07-20

Minor release. One behavior change, one documentation improvement. No bug
fixes in the strict sense — v1.6.0's `WER_MODE=LOCAL` option worked
correctly as designed; this release simplifies the script by removing it.

### Changed
- **Windows Error Reporting is now permanently, unconditionally disabled.**
  The `WER_MODE` toggle (`OFF` / `LOCAL`) introduced in earlier versions has
  been removed entirely — the script no longer offers a way to keep local
  crash dumps while blocking submission to Microsoft. WER is always fully
  off: no local dumps, nothing sent to Microsoft, no user-facing crash
  prompt. If you relied on `WER_MODE=LOCAL`, see "Upgrading from 1.6.0"
  below before running this version.

### Added
- A clarifying comment in the per-user settings section explaining that
  when this script is run via "Run as Administrator" using a different
  account than the one you're logged into, `HKCU` refers to the admin
  account's profile — the logged-in user's profile is still covered
  separately by the per-profile loop, but won't reflect changes until they
  log out and back in.

### Upgrading from 1.6.0

Safe to run v1.6.1 directly over a machine already hardened by v1.6.0 — no
need to roll back 1.6.0 first, no reboot-then-repair sequence required.
Every run is self-contained: it creates its own fresh
`PrivacyLockdown_<timestamp>` folder, backs up whatever it finds in the
registry *at that moment*, and writes its own `rollback_privacy.bat`. It
never reads or depends on any previous run's folder.

One thing worth understanding about what that means in practice:

- Each run's backup captures a key's value **as found when that run
  starts** — not "the original factory default." So the backup v1.6.1
  creates on a machine v1.6.0 already hardened captures the *1.6.0-hardened
  state*, not stock Windows defaults.
- That means **your original v1.6.0 `PrivacyLockdown_<timestamp>` folder is
  your only path back to stock Windows defaults.** Keep it. The rollback
  script generated by a 1.6.1 run only reverses what *that run* changed.
- In practice, if your 1.6.0 run used the default `WER_MODE=OFF`, running
  1.6.1 afterward just re-applies the same four WER policy values — no
  actual change occurs, and the rollback script for that run technically
  contains entries for every key touched (since it snapshots each key on
  first touch regardless of whether anything's about to change), but since
  those snapshots capture the *already-hardened* state, importing them back
  is a no-op. The only place a real difference could occur is WER, and only
  if you'd switched to `LOCAL` mode.
- If you *had* edited v1.6.0 to use `WER_MODE=LOCAL`: v1.6.1 has no code
  path left that reads, writes, or removes the old non-policy
  `HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting` keys or the
  `LocalDumps` subkey (`DumpType`, `DumpCount`, `DumpFolder`) that mode
  created. Running 1.6.1 adds the policy-path `Disabled=1` key alongside
  them. The policy key takes precedence, so WER ends up fully off either
  way — the old `LocalDumps` values are simply orphaned, inert clutter.
  Harmless to leave, or delete
  `HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting` (the non-policy
  branch) by hand afterward if you'd rather clean it up.

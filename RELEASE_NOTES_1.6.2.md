# Privacy-Lockdown-LTSC2021 v1.6.2 — Release Notes

**Repository:** https://github.com/x805/Privacy-Lockdown-LTSC2021
**Previous version:** v1.6.1
**Release date:** 2026-07-23

## Summary

v1.6.2 is a correctness and reliability release. It fixes four bugs that could
cause silent failures in rollback or service hardening on certain systems
(non-English Windows, secondary-admin elevation, moved/renamed backup
folders, or registry values containing spaces), closes a related gap that
could make per-user rollback fail even after the path fix, cuts scheduled-task
processing overhead, and adds three new privacy policies. No architectural
changes: `:EnsureKeyBackedUp`, incremental `rollback_privacy.bat` generation,
and the documented exclusion list (`PcaSvc`, Location Services, `SysMain`,
`WSearch`, Defender cloud protection, Windows Update delivery) are unchanged.

## Fixed

- **Service start-type detection failed on non-English Windows.** `:StopDisableSvc`
  read the service's original start type by parsing `sc qc`'s `START_TYPE` label,
  which is localized (e.g. displays in German/French/Japanese). On non-English
  builds this meant rollback couldn't reliably restore the correct start type.
  Now reads the `Start` value as a `REG_DWORD` directly from
  `HKLM\SYSTEM\CurrentControlSet\Services\<SvcName>`, which is numeric and
  never localized.
- **Active secondary-user profiles were skipped.** Running the script via
  "Run as Administrator" with different credentials than the logged-in user
  meant `HKCU` targeted the admin's own profile, and the standard user's
  `NTUSER.DAT` was locked, so it failed the offline `reg load` used for
  every other profile. That user's settings previously wouldn't apply until
  their next full logon. The script now also enumerates already-mounted
  session hives directly under `HKU` and applies settings to them immediately.
- **Rollback broke if the output folder was moved.** `rollback_privacy.bat`
  baked in this run's absolute `WORKDIR`/`REGBACKUP` path for every
  `reg import` command. Moving, renaming, or copying the `PrivacyLockdown_*`
  folder to another location silently broke rollback. Backup file references
  now resolve relative to `rollback_privacy.bat`'s own location at rollback
  time.
- **Per-user rollback could silently no-op even with the path fix above.**
  `reg export`/`reg import` for offline and Default-template profile hives
  referenced a `TempHive_<profile>` mount name that only exists for the
  duration of the run that created it — by the time rollback runs, that mount
  is gone, and `reg import` against it creates a disconnected key instead of
  restoring anything, with no error. Rollback now re-mounts each profile's
  `NTUSER.DAT` under that same name before replaying the recorded commands,
  then unmounts it.
- **A profile folder name containing certain characters could corrupt output.**
  The loop over `%SystemDrive%\Users\*` stored each folder name into a
  delayed-expansion variable, which breaks if the name contains a literal `!`.
  Moved to a dedicated subroutine using argument substitution instead, which
  isn't affected by this.
- **Registry values containing spaces could fail to write.** `:SetReg`'s
  `reg add` call passed data unquoted; string values with spaces could break
  the command. Data is now quoted.

## Changed

- **Faster scheduled-task processing.** `:DisableTask` no longer spawns a
  PowerShell process per task to check its current state — it uses native
  `schtasks /query /fo CSV /nh` instead. **Trade-off:** the task-state text
  `schtasks` prints is a localized display string (unlike the previous
  PowerShell `.State` enum), so on non-English Windows this could miss
  detecting an already-disabled task and cause rollback to re-enable it. This
  only affects that rollback decision — the disable action itself uses exit
  codes, not this text, and is unaffected.

## Added

- **Cloud Clipboard**: cross-device clipboard sync/telemetry disabled via
  `AllowCrossDeviceClipboard = 0`.
- **News and Interests / Widgets**: background content feed disabled via
  `AllowNewsAndInterests = 0`.
- **Edge Update tasks**: `EdgeUpdateTaskMachineCore` and
  `EdgeUpdateTaskMachineUA` added to the scheduled-task disable list.

## Upgrade notes

- If you have a `rollback_privacy.bat` generated by v1.6.1 or earlier, **run
  it before upgrading** if you intend to roll back — v1.6.2's script doesn't
  retroactively fix an already-generated rollback file.
- No config file or command-line changes. `/quiet` behaves the same as before.

## Known limitations

- On non-English Windows installs, rollback's decision to re-enable a
  previously-enabled scheduled task relies on a localized status string (see
  "Changed" above) and may not always detect a task that was already disabled
  before this script ran.
- Rollback for a currently-logged-in secondary user's profile (the new
  active-session handling) only reaches that profile if the same user is
  still logged in when rollback is run; if they've since logged off, that
  profile falls back to being reachable through the normal offline
  reload/unload path instead.
